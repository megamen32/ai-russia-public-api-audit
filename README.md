# Аудит витрины AI Russia

Скрипт не доверяет счётчику «сценариев» на главной и отдельно считает:

1. публично обнаруженные URL;
2. валидные страницы карточек;
3. уникальные нормализованные тексты;
4. каждое уникальное размещение карточки в ячейке `отрасль × бизнес-функция × бизнес-задача`;
5. повторное использование одного URL в разных ячейках;
6. карточки, совпадающие по названию или содержанию с официальным `AI Alliance Casebook 2024`;
7. доказательность того, что карточка описывает фактически внедрённый проект.

Критически важно не смешивать три величины: **URL карточек**, **уникальные тексты** и **размещения в матрице**. Один и тот же URL может участвовать во многих ячейках и раздувать агрегированный счётчик без появления нового текста или нового внедрения.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements_ai_russia_audit.txt
playwright install chromium
```

## Полный запуск

```bash
python ai_russia_audit.py --out ai_russia_dump
```

Более наглядная отладка браузера:

```bash
python ai_russia_audit.py --out ai_russia_dump --headful --verbose
```

Повторный запуск использует кэш карточек. Для чистого обхода:

```bash
python ai_russia_audit.py --out ai_russia_dump --no-resume
```

Щадящий тест на небольшой выборке:

```bash
python ai_russia_audit.py \
  --out ai_russia_test \
  --max-pages 40 \
  --browser-discovery-pages 5 \
  --common-crawl-indexes 1
```

Если Chromium не запускается, можно оставить только HTTP + Jina Reader. В этом режиме восстановление матрицы будет слабее, потому что XHR браузера не перехватываются:

```bash
python ai_russia_audit.py \
  --out ai_russia_dump \
  --no-browser-discovery \
  --no-browser-fetch \
  --use-jina
```

## Как обнаруживаются страницы

Скрипт объединяет несколько независимых источников:

- ссылки и XHR/fetch-ответы текущей витрины;
- годовые индексы старой библиотеки AI Russia Works за 2018–2021 годы, где собраны исходные поданные/проверенные проекты;
- сериализованное состояние Nuxt/SPA;
- `robots.txt` и sitemap;
- последние индексы Common Crawl;
- Wayback CDX для старых slug;
- предсказуемые диапазоны `ml001…` и `genai001…`;
- необязательный собственный файл URL через `--urls-file`.

Это надёжнее обхода только видимых карточек. Тем не менее математической гарантии найти осиротевший URL, отсутствующий во всех публичных индексах и ответах сайта, нет.

## Градация кейсов

Классификатор не использует «AI detector» и не пытается доказать авторство текста.

- `A_source_backed_implemented` — назван внедренец, есть признаки фактического запуска, фактическая метрика в результатах и явный раздел источников либо старый знак экспертной проверки.
- `B_documented_implemented` — достаточно конкретно заявлено состоявшееся внедрение, но доказательная цепочка слабее A.
- `C_named_but_weakly_evidenced` — организация названа, однако запуск или результат нормально не подтверждены.
- `D_scenario_or_potential` — каталожное применение, будущий/тестовый проект, преимущественно потенциальные формулировки, перечень поставщиков без внедренца либо карточка из Casebook без конкретного внедрения.
- `E_unclear` — данных не хватает либо разметка страницы не разобрана уверенно.

A и B попадают в `real_candidates.csv`, но остаются **кандидатами**, а не автоматически доказанными фактами. C и E идут на ручную проверку. Проценты вида «до 40%» не считаются фактическим результатом сами по себе: Casebook 2024 прямо допускает «реальные/потенциально достижимые» эффекты.

Внедренец может быть осторожно выведен из предложения вроде «ПАО X внедрило систему…». В таком случае поле `adopter_inferred_from_text=true`, а точное предложение сохраняется в `adopter_evidence_excerpt`.

## Основные результаты

- `report.md` — сводка.
- `all_cards.csv` / `all_cards.jsonl` — все разобранные карточки и признаки.
- `real_candidates.csv` — сильные кандидаты на реальные внедрения.
- `named_weak_claims.csv` — организация названа, но доказательств мало.
- `catalog_scenarios.csv` — потенциальные/каталожные сценарии.
- `manual_review.csv` — неоднозначные карточки.
- `verification_queries.csv` — запросы для независимого фактчекинга A/B/C.
- `taxonomy_placements.csv` — одна строка на уникальное размещение URL в ячейке матрицы.
- `placement_reuse.csv` — сколько ячеек и отраслей занимает каждый URL.
- `matrix_counts.csv` — число уникальных URL, уникальных текстов и классов A–E в каждой ячейке; отдельные флаги `exactly_five_urls` и `exactly_five_texts`.
- `exact_duplicate_groups.csv` — точные дубли после нормализации.
- `near_duplicate_pairs.csv` — близкие тексты по char-TF-IDF.
- `repeated_sentence_openings.csv` — повторяющиеся начала предложений.
- `network_endpoints.csv` — найденные API/XHR endpoints.
- `network_records.jsonl` — извлечённые из API/SPA записи с контекстом матрицы.
- `discovery_sources.csv` — откуда найден каждый URL.
- `casebook_fingerprint.json` — структурный отпечаток официального сборника.
- `raw/` — HTML, JSON, sitemap и другие доказательные артефакты.

## Самые полезные проверки

```bash
# Сколько уникальных URL реально найдено и сколько у них уникальных текстов
python - <<'PY'
import pandas as pd
x = pd.read_csv('ai_russia_dump/all_cards.csv')
print('URL:', x.url.nunique())
print('Тексты:', x.content_hash.nunique())
print(x.grade.value_counts(dropna=False))
PY

# Какие URL сильнее всего переиспользуются в матрице
python - <<'PY'
import pandas as pd
x = pd.read_csv('ai_russia_dump/placement_reuse.csv')
print(x.sort_values('placement_count', ascending=False).head(30).to_string(index=False))
PY

# Насколько массово встречается квота ровно пять
python - <<'PY'
import pandas as pd
x = pd.read_csv('ai_russia_dump/matrix_counts.csv')
full = x[x.industry.notna() & x.business_function.notna() & x.business_task.notna()]
print('Полных ячеек:', len(full))
print('Ровно 5 URL:', full.exactly_five_urls.sum())
print('Ровно 5 текстов:', full.exactly_five_texts.fillna(False).sum())
PY
```

## Формулировка, которую выдерживает проверка

Самый защищаемый вывод строится не как «это написал ChatGPT», а так:

1. сайт смешивает потенциальные сценарии, заявленные внедрения и старые экспертно проверенные кейсы;
2. часть карточек прямо происходит из официального каталога перспективных решений;
3. у многих карточек нет конкретного внедренца, фактического результата и проверяемого источника;
4. агрегированный счётчик может отражать размещения по таксономии, а не число уникальных текстов или проектов;
5. реальные кейсы нужно считать только после дедупликации и проверки первоисточников.

Перед публичным обвинением откройте первоисточники и вручную проверьте строки из `real_candidates.csv` и `named_weak_claims.csv`.
