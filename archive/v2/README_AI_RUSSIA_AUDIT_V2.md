# AI Russia API Audit v2

Исправленный аудитор текущей версии `ai-russia.ru`.

## Главное исправление

Ответ `/api/scenarios` пагинирован. Поле `scenarios` содержит только текущую страницу, а поле `total` - полный размер выборки.

В приложенном образце:

- глобальный запрос вернул 20 объектов, но `total: 4992`;
- запрос `?industry=agriculture` вернул 20 объектов, но `total: 500`.

Поэтому 13 связанных кейсов и две компании, найденные на первой странице, нельзя объявлять итогом всей базы.

## Что делает v2

1. Получает 10 отраслей из `/api/industries`.
2. Сохраняет матрицы `/api/industries/<slug>/matrix`.
3. Автоматически ищет рабочую схему пагинации `/api/scenarios`.
4. Если обычная пагинация не обнаружена, подбирает параметры фильтра по бизнес-функции и задаче и обходит матрицу по ячейкам.
5. Разделяет сценарии и реальные кейсы по полям `caseCount` и `cases[]`.
6. Дедуплицирует кейсы по cuid.
7. Для каждого открытого case ID запрашивает `/api/cases/<cuid>` и сохраняет полный ответ.
8. Отдельно показывает полноту обхода. Неполный результат не выдаётся за итоговый счётчик.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements_ai_russia_audit_v2.txt
```

## Полный живой обход

```bash
python ai_russia_api_audit_v2.py \
  --out ai_russia_api_dump \
  --verbose
```

Основные результаты:

- `all_scenarios.csv` - все перечисленные сценарии;
- `all_cases.csv` - уникальные открыто видимые кейсы;
- `industry_coverage.csv` - доказательство полноты обхода;
- `matrix_cells.csv` - все матричные ячейки;
- `case_details.jsonl` - ответы `/api/cases/<id>`;
- `raw_api/` - исходные ответы сервера;
- `report.md` и `summary.json` - итог.

## Проверка на сохранённом образце без сети

```bash
python ai_russia_api_audit_v2.py \
  --fixture a9b987a4-093c-4987-b915-53aa4e902c4a.json \
  --out fixture_report
```

Такой прогон должен честно показать:

- `ALL: returned_rows=20, api_total=4992, complete=False`;
- `agriculture: returned_rows=20, api_total=500, complete=False`;
- 13 связанных кейсов - только в наблюдавшейся странице, не во всей базе.

## Как читать итог

Надёжный счётчик реальных открытых кейсов - это число уникальных `case_id` после **полного** обхода, когда `enumeration_complete=true` для всех отраслей.

Сумма `caseCount` может быть больше числа открытых `cases[]`: часть кейсов может быть скрыта авторизацией или один кейс может быть связан с несколькими сценариями. Поэтому отчёт выводит все три числа отдельно.

## Известные факты из приложенного образца

- Сумма отраслевых `scenarioCount` равна 4992.
- В матрице сельского хозяйства 100 ячеек, у всех `count: 5` и `hasCases: false`.
- Глобальная первая страница содержит 13 открыто показанных case ID от Альфа-Банка и Яндекса.
- Это выборка первой страницы, а не доказательство, что на всём сайте только 13 кейсов.

## Почему старый аудитор дал ноль карточек

Текущий сайт - SPA. Любой `/library/<slug>`, включая выдуманный, отдаёт одну и ту же HTML-оболочку. Данные надо получать из `/api/*`, а не парсить серверный HTML.
